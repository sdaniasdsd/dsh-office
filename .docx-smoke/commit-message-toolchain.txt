dsh-toolchain: 接收 DSH Office 运行时工具链交接（0.9.0）

从 sdaniasdsd/dsh-office 拆出来的运行时职责落在这里：Windows x64 上的私有 Python 3.13、
LibreOffice、Poppler，供 @deepseek-ai/dsh-docx 按契约使用。插件本体不再捆绑这 1.6 GB。

- scripts/fetch-runtime.ps1：上游下载 + 逐条 sha256 校验（python 3.13.15 embed、LibreOffice 26.8.0
  的 MSI 管理式解包、poppler 26.09.0，以及 lxml 6.1.0 / python-pptx 1.0.2 / pillow 12.3.0 /
  xlsxwriter 3.2.9 / typing_extensions 4.16.0 五个 wheel），目标目录用 -RuntimeRoot 指定，
  默认 runtime/win32-x64。与 dsh-office 里那份是同一套配方，只改了这一处参数化。
- scripts/verify-runtime.mjs：12 项验收——三件二进制的自报版本、插件真正 import 的 5 个 Python 包、
  每个组件的体积与文件数、runtime.json 的 schema/platform/components。本机对 0.9.0 实跑全部通过、
  退出码 0（回执写在 README 里）。
- docs/CONTRACT.md：与插件唯一的耦合面——三个绝对路径 + 可选 runtime.json；解析优先级
  （插件配置 → 环境变量 → 兄弟包 → 自带目录）；缺运行时的降级语义（不致命、只让相关能力
  返回 ENGINE_UNAVAILABLE，docx_doctor 逐项报告）；验收清单与三组真实调用对照表。
- docs/COMPONENTS.md：组件版本、体积、文件数、上游 URL 与许可文件位置，全部是本机实测回执。
- runtime.example.json：0.9.0 的实际清单，可直接当样板。

运行时二进制不入库（1.67 GB），走 Release 资产；仓库里只有配方、验收脚本与契约文档。
