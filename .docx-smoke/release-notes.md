# @deepseek-ai/dsh-docx 0.7.0

DSH 的 DOCX 能力插件包：九个 DOCX 模块（dual IR 解析、样式、就地编辑、渲染、版本化交付）＋
随包运行时（Python 3.11、LibreOffice 26.8.0.3、poppler 26.09.0），解压即用，无需另装依赖。
本包由仓库 `the-last-docx/` 的源码在 commit `05cac74` 上构建。

## 本版重点：参照文档重建时，把「格式」也带过去

上一版的参照路径只搬文字和结构，于是用一份已批准的标准样例重建劳动合同时，格式对不上：

- 签署栏单元格 11.5 pt（正文是 12 pt）——表格字号被寄存器压了一档；
- 附件表头 12 pt，而标准样例是 10.5 pt 黑体 —— 单元格自己的字号没有被携带；
- 9 行单位/个人信息行被缩进 2 字符（8.5 mm），标准样例是齐左；
- 居中的副标题被缩进顶偏 4.3 mm。

现在：

- `docx-parse` 新增首行缩进观察，**解析样式链**（段落直接声明 → basedOn → docDefaults）后给出有效值；
  「谁都没声明」上报为 0，只有样式表读不到时才上报为「没有观察」。
- `docx-create` 新增 `cellFormats`（单元格自己的字号/字体/加粗，`bold: false` 可覆盖首行默认加粗）
  与 `firstLineIndentPt`（**0 是陈述，不是缺省**）；`plain`（正式文书）寄存器表格文字与正文同号。
- 参照映射器携带 run 字号与中文字体、单元格格式、首行缩进，并在报告里写明近似之处
  （每段一个字号，取文本最多的 run；不带颜色）。
- MCP 握手版本号改为由打包脚本注入，不再硬编码（此前装成 0.6.0 仍自称 0.5.0）。

## 与标准样例的对照（同一 LibreOffice 26.8.0.3 渲染）

| 项 | 标准样例 | 本版产物 |
| --- | --- | --- |
| 声明字号 | 22 / 14 / 12 / 10.5 pt | 22 / 14 / 12 / 10.5 pt |
| 11.5 pt | 0 | 0 |
| 中文字体 | 黑体 23 / 宋体 58 / 楷体 2 | 黑体 23 / 宋体 57 / 楷体 2 |
| 有效首行缩进 | 480 twips×40 段 / 0×35 段 / 420 twips×1 | 同 |
| 首页信息行左边界 | 30 mm | 30 mm |
| 首页居中副标题 | 93.3 mm | 93.3 mm |

仍不一致：`第一条` 与标题之间标准样例是 2 个 ASCII 空格、本包产物是 1 个（解析侧的排版空白归一化）；
页脚分隔宽度；以及换行位置——单变量实验证明它来自标准样例把东亚语言标成 `en-US`
（本包产物标 `zh-CN`，因此按中文排版规则允许行末标点悬挂）。

## 安装

在 DSH 的 profile 目录里把它作为本地依赖装进去：

```bash
pnpm add "@deepseek-ai/dsh-docx@file:/绝对路径/deepseek-ai-dsh-docx-0.7.0.tgz"
```

安装后需重启 DSH，让 MCP 客户端重新拉起插件进程。握手回执里会显示
`serverInfo.version = 0.7.0`。
