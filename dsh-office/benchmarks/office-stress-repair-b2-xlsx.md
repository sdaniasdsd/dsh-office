# Office DSH Repair Batch 2 — XLSX print pagination

Date: 2026-09-27  
Status: implemented and visually reviewed under LibreOffice. Remaining page fragmentation is documented below; this is not Microsoft Excel equivalence.

## Attention lock

Only print settings on the listed worksheets may change. Preserve cell values, formulas, styles, defined names, external relationships, and all unrelated package content. For wide data sheets, use landscape, one page across, and leave page height unlimited. The short `Lookups` sheet uses one page tall to avoid separating its small lookup tables. Do not remove rows/columns, invent print areas, hide sheets, or rewrite the workbook through ExcelJS.

## Root cause and route

The prior LibreOffice-only previews showed a 24-page condition-survey workbook and a 19-page modelling-QA workbook, with several wide sheets split across horizontal print pages. The DSH `xlsx.readRange` lane was successful (50/50); this was a print-layout capability gap, not a cell-reading defect. The source workbooks contain package features such as external links, drawings, ActiveX/custom XML, or named ranges that cause the existing ExcelJS cell-write path to refuse a full-workbook save.

Added `xlsx-office.execute` action `setPrintLayout`, backed by a package-scoped OOXML edit using `fflate` and `@xmldom/xmldom`. It resolves requested sheet names through the workbook relationships and edits only worksheet `pageSetUpPr/@fitToPage` and `pageSetup` print properties. It refuses digitally signed workbooks, writes a separate immutable artifact, reopens it with ExcelJS, confirms the worksheet XML differs only in requested print settings, and checks that every non-target ZIP part is byte-for-byte unchanged. Existing `setCells` safeguards remain unchanged. Microsoft’s SpreadsheetML documentation defines `fitToPage` on `pageSetUpPr` and `fitToWidth`/`fitToHeight` on `pageSetup`; the values are bounded by Excel’s supported ranges ([`pageSetUpPr` documentation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.pagesetupproperties?view=openxml-3.0.1), [Microsoft implementation notes for `pageSetup`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/7d79dcce-d8fb-43da-a189-f0e46658da62)).

The selected policy is deliberately conservative: fit width, never force a long form to one page tall. A single-page-wide export was rejected for any sheet whose visual result became clipped or obviously illegible; no workbook data was changed to improve the page count.

## Limits and next action

This batch adds a safe, opt-in DSH print-setup writer; it does not automatically determine correct print areas or hide “instruction” worksheets. The residual QA Lookup tail page appears under LibreOffice even with the requested fit settings. Removing it would require a separate renderer/source investigation (and probably a worksheet-specific print range or native Excel comparison), so it remains visible and unmodified rather than being declared repaired.
