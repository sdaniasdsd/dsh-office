# 真实 PDF 适配器验收计划

基线数字、通过范围及欠缺见 VALIDATION.md。这个清单跟踪扩大到真实用户语料时所需的验收样本，并避免把少量自建样张等同于上线资格。

## 样本与证据

| 样本 | 必须核对的结果 |
| --- | --- |
| 原生中英文、子集字体与缺失 ToUnicode | 已知文字 ground truth；提取失败应标 partial，不能造字 |
| 旋转 0/90/180/270、非零 CropBox、UserUnit | 页图上叠加来源框，核对全部角点与页内方向 |
| 双栏、标题、跨页段落 | 独立阅读顺序与语义分段 ground truth（Docling 现提供候选结果，语料准确性未测） |
| 有线/无线表格、合并单元格、跨页续表 | 网格、跨度、单元格文字及来源矩形；必须对照原始 Docling observation 检查 mapper |
| 纯扫描、混合原生/扫描页、中文低清页 | 页级覆盖、OCR 字符误差，避免原生层与 OCR 重复 |
| AcroForm、多 Widget 同字段、中文字段 | Fields/Widget 的有效值与 appearance 一致，重开后仍交互 |
| 带批注、嵌入文件、JavaScript、外链、XFA | 检测覆盖明确；未扫描项为 unknown；无动作执行 |
| 加密、签名、多次增量更新 | 密码通过宿主能力获取；签名存在/密码学有效性/修改影响分开 |
| 截断、损坏 xref、巨大图片、超多对象 | 分类错误、恢复告警、超时和预算有效 |
| 创建/编辑后的 PDF | 新产物可重开，源文件摘要不变，文字/字段/页序等请求确实落地 |

当前集成样张是本机 PDFKit 生成的两页中文原生 PDF、表格、表单和派生的 raster-only PDF。它可重复且没有第三方数据权利问题，但不代表真实合同或用户扫描件。后续引用上游测试 PDF 作为 fixture 时，应逐个登记 URL、license、SHA 与期望结果；第三方 PDF 只作数据输入。

## 四层验证

1. 结构：PDF.js 重新打开并使用 qpdf 检查；qpdf warning 不计为结构 pass。
2. 内容：重开输出，按请求核对页序、字段、文本或删隐结果；不能以 PDF 可打开代替。
3. 来源：源 id+sha、预览源摘要、每个图像及证据文件摘要绑定同一修订；修改之后旧 IR/旧图不得复用。
4. 视觉：PDF.js 渲染 PNG，并用 Poppler 在独立后端对照样张。自动化项目仍不自行将 visualReview 标 reviewed；缺字、遮挡、裁切、断页需逐页人审。

当前样张的 PNG 已检查。对任意后续 PDF 工件，必须重新渲染检查。生成 PNG 本身不会自动把 visualReview 改为 reviewed。

## 运行与交付

记录引擎/模型版本、系统、字体、每页耗时、峰值内存、页数与模型冷启动时间。qpdf/Docling abort 会回收子进程；解析/渲染同步 CPU job 还需服务部署加 worker/进程 resource limit。

本地区版本存储以原子 hardlink 追加递增 revision，并核验父版本摘要；相同字节的同路径幂等，冲突文件拒绝覆盖。正式宿主适配仍需用 office-files 的并发 CAS 实现替换本地 store。超时不能推断提交未发生。还需测并发、丢失确认、旧预览和伪造桥接来源。

定义超限行为：输入字节、解码对象/流、页面数、单页像素、全部图片字节、OCR 页面数、输出 JSON、总输出字节及执行时间。公共 runtime 与适配器已实现基本输入/输出、页数、IR 节点、产物、像素和子进程 stdout/stderr 上限；PDF 库内部瞬时 RSS 仍需宿主隔离。
